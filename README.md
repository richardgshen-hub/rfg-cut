# RFG Cut

<p align="center"><img src="./public/brand/rfg-cut-icon-512.png" width="150" alt="RFG Cut icon" /></p>

<p align="center">AI 驱动、人工复核优先的中文口播与访谈剪辑工作台。</p>

RFG Cut 把真实素材、带时间码原话、目标成稿和内容 Brief 放进同一条工作流。它适合两种常见任务：照准备好的采访稿找原话并重排，以及把无序口播整理成更顺的一段话。

## 现在能做什么

- 导入真实视频或录音，素材持久保存在本机 `.rfg-cut/` 工作区。
- 导入 SRT、VTT 或逐行时间码文本；也可用浏览器内 Whisper Tiny 做中文转写。
- 按目标成稿顺序匹配原片原话；匹配不到或有歧义的句子会明确保留为待处理项。
- 让 Codex 读取 Brief 和完整逐字稿，回传带原片证据的叙事重排草案。
- 逐段试听、调整入点/出点、排序、撤销、重做并人工确认。
- 用本机 FFmpeg 真正导出重排后的 MP4，并查看异步导出进度。
- 下载重新计时的成片 SRT、原片 SRT、项目备份和剪映交接 JSON。
- 标记可能的口癖、停顿和换气口；在没有逐词切点证据时只做候选提示，不假装已经精确删除。

## 一键启动

需要 Node.js 22+ 和 FFmpeg：

```bash
npm install
npm start
```

然后打开 [http://127.0.0.1:5173](http://127.0.0.1:5173)。`npm start` 会同时启动网页和本机媒体服务，不需要再开第二个终端。

## AI 驱动路线

`plugins/rfg-cut-agent/` 是配套的 Codex 插件。RFG Cut 不在网页里索要 OpenAI API Key，也不冒充可以直接调用 ChatGPT 订阅；理解稿件的工作由用户当前的 Codex 宿主完成。

1. 在编辑器中导入素材与带时间码原话。
2. 点击「整理口播」里的「复制 AI 编辑任务」。
3. 把任务粘贴给装有 RFG Cut Agent 的 Codex。
4. Codex 通过本机 MCP 读取当前上下文，并回传待复核草案。
5. 在编辑器中试听、确认，再导出。

每次任务都绑定 `contextId + projectId + sourceId`。更换素材、修改逐字稿或改动 Brief 后，旧草案不会被当作当前结果。MCP 只接受逐字稿中存在的完整原话边界；素材文件不交给模型。

## 剪映联动边界

当前输出的「剪映交接包」包含原片标识、Brief、目标稿、原稿、顺序片段与真实时间码，便于在剪映中复核落剪。它不是剪映原生草稿文件，也不会写入剪映的私有工程格式。MP4 初剪与配套 SRT 已可直接导入剪映继续包装。

## 数据与限制

- 本机服务只监听 `127.0.0.1`，拒绝非本机 Host 与网页来源。
- 媒体、导出任务和 AI 上下文持久化在被 Git 忽略的 `.rfg-cut/` 目录。
- 浏览器内转写首次需要下载 Whisper 模型；Tiny 模型速度优先，中文准确率仍需人工校对。
- 句级逐字稿无法证明某个句内口癖的精确波形位置，因此不会自动删除整句。
- 当前只处理单个素材源；多机位同步、自动 B-roll 和剪映原生工程写入不在 v0.2 范围内。
